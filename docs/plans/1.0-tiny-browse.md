# whatcmd 1.0: tiny-browse as a real dependency

Branch: `release/1.0.0` (cut from `release/0.2.0` at `e40656f`, which already holds `/w+` refine,
the first web lookup and the hook spinner). Ships as **1.0.0** through a PR to `main`; the
release workflow publishes to npm on every push to `main`.

## Where things stand

- npm has `@shubhamcodess/whatcmd@0.1.0` and `@shubhamcodess/tiny-browse@0.1.0`.
- `release/0.2.0` was never pushed or published. Its web lookup works but:
  - depends on `"tiny-browse": "file:../tiny-browse"`, which breaks on CI and for npm users;
  - talks to tiny-browse by spawning its MCP server (`src/mcp.ts`), a second Node process per lookup;
  - knows nothing about tiny-browse's budgets: a `blocked` answer is just text it greps for "CAPTCHA".

## What tiny-browse gives us (library, `0.1.x`)

- `createClient(opts)` → `webSearch` / `webFetch` / `close`; one-shot `webSearch` / `webFetch`; `doctor()`.
- `TinyBrowseError.code`: `chrome_not_found | timeout | blocked | network | private_address | aborted | invalid_input`.
- `SearchResult`: `provider`, `cached`, `warning` (degraded engine), `attempts[{provider,status}]`, `pages`, `markdown`.
- Options: `signal`, `timeoutMs`, `mode: "http"` (no Chrome), `useServer: "auto"` (reuse a running `tiny-browse serve`), `logger`.
- **Rate limits are enforced inside tiny-browse and shared by every tiny-browse process on the machine**
  (files in its cache dir): Google 8 s gap, 3/min, 20/h, 100/day; DDG/Bing 3 s gap, 6/min, 60/h, 300/day;
  after a CAPTCHA an engine pauses 15 min → 1 h → 4 h → 24 h. Over budget = engine skipped, next one tried;
  all refuse = `blocked`.
- Its own cache: pages 1 h, search results 10 min.

## Design

### 1. Dependency

- `dependencies: { "@shubhamcodess/tiny-browse": "^0.1.0" }` (zero deps, 126 kB, so a plain dependency, not optional).
- Pin to `^0.1.0`: before 1.0 a minor bump is breaking, so `^0.1` keeps us on 0.1.x.
- Loaded with a lazy `await import(...)` inside `browse.ts`, so `web` off never loads it.
- Delete `src/mcp.ts`, `resolveBrowse`, the `webCommand` setting and its docs (2.0 is the time to drop it).

### 2. Respecting rate limits

whatcmd adds no limiter of its own for engines; it lets tiny-browse's shared budget decide and stays polite on top:

- **Never pass `config`** to tiny-browse: that would skip the user's `~/.config/tiny-browse/config.json`
  (their own limits, providers, blocked domains). Use the default cache dir so whatcmd shares budgets with
  any tiny-browse MCP server the user runs for their agents. Pass `useServer: "auto"` to reuse a warm one.
- **Per request at most 1 reference-page fetch + 1 search** (today's `webDone` rule, kept), and **no retries
  on `blocked`**.
- **Refine chains don't re-search**: the web excerpt is stored in the `/w+` session file and reused for
  the next refinements; a new lookup only if the change names a different tool.
- **Cooldown on `blocked`**: when every engine refused (`blocked`, or all `attempts` over budget/paused),
  write `web/cooldown.json` for 15 min (matching tiny-browse's first pause). During it, skip search
  (reference pages still read, they aren't search engines) and say once, dimmed:
  `web search paused (search engines rate-limited), using local docs`.
- `warning` set (degraded engine) → treat the excerpt as low trust: use it only if it contains the tool name
  (already enforced by `webExcerpt`), and cache "nothing found" for 1 h, not 7 days.
- Reference pages are fetched with `mode: "http"` (static docs, no Chrome, no search budget used).
  Search uses Chrome mode so Google is available.
- `AbortSignal` tied to `webTimeoutMs` and to Ctrl-C, so a stuck lookup never holds the shell.

### 3. When to go to the web ("hard" commands only)

The model must try first; web is the escalation. Keep the existing three triggers, made explicit:

| Trigger | Today | 2.0 |
|---|---|---|
| Tool with shallow local `--help` (kubectl, helm, gcloud, az, gh, …) | reference page read up front | same, `mode: "http"`, cached 7 days |
| Model answers `SEARCH: <query>` | yes | same; query passed through `cleanQuery` (no paths, secrets, long numbers leave the machine) |
| Answer still fails the checks after the second chance | search | same, plus: **flag not in local help** (lint finds an unknown option for the named tool) counts as failing |

Plain requests (`find big files`, `tar this folder`) keep the exact prompt and zero network calls.

### 4. Settings and UX

- `web`: `true` default, used only after a failure (see Decisions).
- `--web` / `--no-web`, `WHATCMD_WEB`, `webTimeoutMs` stay.
- Spinner (hook and direct mode) shows a stage: `searching the web…` / `reading kubernetes.io…`.
- After the command: dim `used web docs from kubernetes.io` (exists), plus `(cached)` when no request was made.
- `--debug` notes gain `provider`, `cached`, `attempts` and budget state.
- `whatcmd doctor`: calls tiny-browse `doctor({ startChrome: false })` and prints browser found + engine
  budgets/pauses, so "why didn't it search?" has an answer.

### 6. Tests and evals

- Unit (`web.test.ts`): fake client returning `blocked`, `warning`, `cached`, timeout; asserts no retry after
  `blocked`, cooldown written and honoured, refine reuses the doc, web off never imports the package.
- `npm run eval` (local cases) unchanged with web off: no regression allowed.
- `npm run eval:web` (40 cloud-CLI cases): baseline 29/40 with the MCP path; target ≥ 29/40, with a
  pacing note since a full run is ~40 searches and will hit the Google hourly budget (run with
  `TINY_BROWSE_PROVIDERS=duckduckgo,bing` or spread across an hour).
- `npm run check` (pack contents, links); CI on Node 22/24 with the npm dependency (no sibling checkout).

### 7. Release

1. Commits on `release/2.0` (feature branches merged in, as on 0.2.0).
2. Push `release/2.0`, open PR → `main` with the changelog.
3. Merge: `release.yml` builds, tests and publishes `@shubhamcodess/whatcmd@2.0.0` with provenance,
   creates the GitHub release; Pages redeploys the site.

## Decisions

1. **`web` defaults to on**, but a lookup happens only after the model failed on that request
   (`SEARCH:` answer, or an answer that still fails after the retries). The up-front reference-page
   read of 0.2.0 is gone: correct answers never touch the network.
2. **Version 1.0.0** (0.2.0 was never published).
3. **Dependency range `^0.1.0`**: new installs get the newest 0.1.x patch; a breaking tiny-browse 0.2
   needs a deliberate bump here (Dependabot opens it).
4. Not done in 1.0: the "unknown flag" trigger (lint has no per-tool flag check yet) and spinner stage text.
